## Goal

Let SDK contact sessions dispatch fresh admin-tier ephemeral sessions to **triage novel failures autonomously**, with structured results injected back into the originating session — so the assistant can self-heal problems it has never seen before instead of texting the admin for manual debugging.

**Concrete trigger:** today's chrome-control incident, where the agent texted the admin "service worker hung again" instead of running `ps`, sampling the runaway native_host PID, reading the source, and proposing a kill. A Claude Code session (this one) had the tools to do that triage; SDK contact sessions don't have an ergonomic equivalent.

**Success criteria:**
1. From any SDK session, `claude-assistant dispatch-investigation "<prompt>"` returns a `task_id` immediately and queues a background investigator.
2. The investigator runs to completion (or timeout/cancel), producing a structured result block.
3. The result is injected back into the originating session, ready to be acted on next turn.
4. The investigator cannot mutate state, send messages, or dispatch its own investigations unless `--allow-mutations` was passed.
5. End-to-end audit trail in bus.db plus a transcript at `~/transcripts/investigations/<task_id>/`.

## Notes

### Architecture decision: piggyback on existing ephemeral-task path
The dispatch system already has agent-mode ephemeral tasks (see `_handle_task_requested` and `create_ephemeral_session`). New work is **not** a parallel system — it's a specialization of the existing path with two new payload fields (`investigation: true`, `notify_session`) and one new code branch in `_handle_task_completed`. This keeps the audit story coherent (all events on `tasks` topic) and reuses timeout/cleanup machinery.

### Architecture decision: read-only by default, mutations opt-in
First-run behavior is *diagnose, don't fix.* The investigator returns "RECOMMENDED ACTION: chrome reset" but the originating session decides whether to run it. This protects against a hallucinating investigator nuking state. `--allow-mutations` is for cases where the user explicitly trusts the agent to act (e.g., an admin saying "go figure out why my build is broken and fix it").

### Architecture decision: structured output via template, not a synthetic tool
v1 ships with a free-form template (`=== RESULT ===` block) because it's simpler and lets the investigator narrate before delivering the structured part. If DR-2 busts, fall back to a synthetic `submit_result` tool — that's strictly more reliable but adds harness complexity.

### Open question: should the originator block until the investigation completes?
Default is no — fire and continue. But there are cases where the originator can't make progress without the result (e.g. "I literally cannot send the calendar invite until you tell me whether chrome is fixed"). Could add `--blocking` later if the use case shows up; not in v1.

### Open question: scope of investigator's context
v1: investigator gets ONLY the prompt + admin tier + full skill access — clean slate, no contact-session history. Pro: focused, avoids context contamination. Con: investigator can't reason about "what was the user trying to do when this broke." If DR-2 reveals this matters, add a `--include-context "<summary>"` arg the originator fills in.

### Cost concern
At ~30k input + 10k output tokens per investigation on Opus, each one is ~$0.40 (rough). At 5/hour rate cap that's $2/hour worst case, $48/day if pegged. Realistic usage should be << 1/hour. Worth metering and showing to the admin in `claude-assistant investigations`.

### What we explicitly are NOT building in v1
- Investigators that talk to each other (multi-agent)
- Long-running investigations beyond 30 min
- Investigations that resume across sessions
- Investigation-suggested code edits applied automatically (always require admin approval)
- A Claude Code-style Task/TaskList/TaskOutput tool surface (we'd want this eventually, but v1 ships with CLI only)

### Connection to today's chrome-control work
The `chrome reset` subcommand and the SKILL.md "Recovery" section we shipped today are the *known-recovery* leg of the strategy. This plan is the *unknown-recovery* leg. Both are needed. Rule #1 ("self-heal first") in the global CLAUDE.md will reference both: try the documented recovery, then dispatch an investigation, then escalate.
